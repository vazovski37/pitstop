Pitstop is version control for teams whose code is written by AI agents.

Git merges text, so two agents can each make a clean change and still break each other: one rewrites a function the other was relying on. The merge is green, and nobody notices until the build or a customer does. Pitstop catches it before it lands, and a teammate decides whether it goes in.

Sign in with GitHub

This server has no GitHub sign-in. Paste its server token in the field at the top of the page to continue.

Catches what git cannot see

Every commit says what its agent read and what it wrote. When one change alters a function another change relied on, Pitstop flags the write skew before it lands, even when the text merged cleanly.

A teammate decides, not an AI

The commit waits for your repository's resolver, with its intent, its files and what moved underneath it. Let it through, or send it back with a note and the agent adapts and commits again.

Your architecture, enforced

Write decisions once, like “pages never import the database”. Every agent reads them before it starts, every commit is checked against them, and an agent can lease a hot function while it changes it.

Works with Claude Code in one prompt

Create a repository and paste one prompt into Claude Code. It installs the client, connects your checkout, wires in the Pitstop tools and keeps the checkout in sync while you work.

              Conflicts

              A commit waits here when its agent relied on something another change altered after it read it (write skew). The repository's resolver decides: let it through as it is, or send it back with a note, and the author's agent adapts and commits again.

              Nothing is waiting

              When an agent's commit relies on code another change just altered, it stops here instead of merging silently.

                Brain

                The team's architecture decisions (ADRs). Every agent receives the accepted ones when it starts a task, and every commit is checked against their rules: a violation is refused with the file and line. Accepting or superseding a decision moves the brain version; each change records the version it passed, so older code can be re-checked.

                  Propose a decision

                  Rules every commit is checked against
                  Globs like src/pages/**. Model reviews only advise; they never refuse a commit.

                  Re-check the code

                  Runs the accepted rules over the code at head, and lists changes that landed before a rule existed.

                  Leases

                  Short locks an agent takes on a hot symbol. Another agent's commit that changes it is refused until the lease is released or expires.
