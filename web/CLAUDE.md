# web/ — the website

Owner: **Vazovski** (since 18 October 2026, every folder is).

## Pages (hash routes)
- `#/` home: signed out, the landing (what Pitstop is, the problem with git and many agents, an inline SVG of the model, four features: write skew, a teammate decides, the architecture enforced, one prompt) and "Sign in with GitHub"; signed in, your repositories as cards (`GET /repos`, then each one's members and parked commits for your role, the member count and what waits) and "New repository" under your login (`POST /repos`).
- A repository's header holds its name, head, the stream's status and the tabs. On the Live tab an onboarding checklist (set up Claude, invite a teammate, mark the resolver) shows to a signed-in account until the repository has entries and more than one member (never to the shared token: on a server without sign-in nobody can accept an invite). The Conflicts tab re-reads the parked commits every 5 s while open, and leaves the page alone (and any note being typed) when nothing changed.
- `#/r/<owner>/<name>` a repository: tabs **Live** (below), **Brain** (`#/r/<o>/<n>/brain`, design doc 9: the brain version as a badge on the tab, from `GET /repos/:o/:n/brain` and every `brain` message; the ADRs, accepted first, each with its decision, reason, rules in a sentence and who proposed and decided it; owners Accept or Reject a proposal and Supersede an accepted one, the last two through `#confirm-dialog`; a writer proposes with title, decision, why and a rule builder, one box per rule: kind, files glob, then the module, call, pattern or question; "Re-check now" runs `GET …/brain/recheck` and lists each violation as ADR, `file:line` and detail, then the landed entries that passed an older brain version; the live leases with their holder, expiry and reason, released by an owner or the holder's developer; `brain` and `lease` messages re-render it and go into "As it happens"; an entry's detail shows the brain version it was checked against), **Conflicts** (`/repos/:o/:n/parked`: commits waiting for the resolver, their write skew and files; a resolver lets one through or sends it back with a note), **Members** (`/repos/:o/:n/members`: roles, the resolver flag, invites by GitHub login that turn into membership at first sign-in, remove, leave) and **Set up Claude** (makes a personal token with `POST /tokens` and writes the prompt a developer pastes into Claude Code: install Node, git and jj, `npm install -g <server>/pitstop-cli.tgz`, `pitstop setup <server> <repo> --token … --agent <name>`). The `Agent name` field (`#setup-agent`) names the checkout's agent: without it setup says `<os user>-claude`, and two checkouts of one person would share a name and each other's warnings. Signed in, it starts as the first free one of `<login>-claude`, `<login>-claude-2`, …: setup tokens are named `claude <repo> <agent>`, so `GET /tokens` says which this person already gave, and "Create another token" moves a default on. A typed name is kept; both texts follow it as it is typed, as a lowercase slug (`agentSlug`). The administrator's shared token never goes into a prompt. On screen the token is masked (`setupText` in `app.ts`) unless "Show token" is pressed, so a recording does not publish it; Copy always copies the full text.
- `#/account` personal tokens (make, list, revoke) and sign out.
- On a server without accounts the header takes the shared token instead (kept in `localStorage`).

## The Live tab (the screen judges look at during the demo)
- The log, newest first: LSN, agent, intent, files, checks; repairs highlighted, with the repair's summary under the entry.
- Who's here (presence, design doc 9.5), above the open intents: one line per live worktree, the agent in its own colour (a hash of its name), its developer, working or idle, its intent, its files with unfinished edits as chips (a file two worktrees are both in is highlighted, with who else in its tooltip), its declared symbols, and `applied #N of #head`. Entries fade as they age and are hidden after two minutes without a write (`PRESENCE_TTL_MS`, the server's too) or once departed (a tombstone). The rows are rebuilt only when what they show changes; every 2 s only their fade and age tooltip move on, so a tooltip stays open and the pulse does not restart. The page's copy keeps at most 500 entries, like the server's. "As it happens" says when an agent arrives or leaves.
- Open intents: agent, text, declared symbols, base LSN, last heartbeat.
- Worktrees: one line per connected daemon, `agent-b · applied #3 of #4`, a green mark at the head and a red one with the lag when behind. The name comes from the worktree's open intent; between tasks it is just "worktree".
- "As it happens": entries landing, repairs, write skew the validator reported, warnings between agents, intents opening and closing.
- Click an entry for its files, read/write/signature sets, repairs and check details.

## How it is built
No framework and no bundler: `public/index.html` + `public/style.css`, and `src/app.ts` compiled by `tsc` to one ES module (`npm run build` → `dist/`). It imports only *types* from `@pitstop/protocol`, so nothing from `node_modules` reaches the browser. The server serves `dist/` at `/` (`server/src/app.ts`, `webDir`; `server/src/index.ts` finds it at `web/dist` or `PITSTOP_WEB_DIR`), so the page is same-origin with the API: the session cookie from sign in with GitHub just works, and a shared-token server takes the token from the page's field (kept in `localStorage`, sent as `Authorization: Bearer` and as `?token=` on the stream).

Data: `GET /version`, `GET /me`, `GET /repos`, then one WebSocket to `/stream` subscribed from LSN 0, which replays the whole log and then stays live (`head`, `entry`, `intent`, `warning`, `presence`, `brain`, `lease`). Presence is a CRDT (`packages/protocol/src/presence.ts`): after subscribe the server sends the whole document, then each update, and the page merges them into its own copy with `applyPresence`, which `src/app.ts` repeats in a few lines because the page cannot import runtime code from the protocol (no bundler; a value import would pull zod in). Keep the two the same. Ages count from this browser's clock, or from the newest stamp seen when that is ahead. Switching repositories reconnects; a dropped socket reconnects from the last LSN seen. The worktrees are not on the stream: the page reads `GET /repos/:owner/:name/worktrees` (`WorktreesResponse` in `server/src/app.ts`, a server query rather than a protocol message) on `head`, after every live entry and every 3 s while the socket is up. The Dockerfile builds this workspace into the server image.

## Design system
`public/style.css` starts with the tokens on `:root` (colour: one dark theme, deep neutrals, raised surfaces, one accent, `--ok`/`--warn`/`--bad`/`--repair`; spacing `--s-*`; radius `--r-*`; `--font-sans` for the interface, `--font-mono` only for code, ids, LSNs and paths), then the components: `.btn` (`-primary`, `-secondary`, `-ghost`, `-danger`, `-ok`, sizes `-sm`/`-lg`), `.input`/`.select`/`textarea` with `.field`/`.field-label`, `.switch`, `.card`, `.badge` (`ok`, `warn`, `bad`, `repair`, `accent`), `.pill`, `.avatar`, `.agent` chips, `.tabs`, `.empty-state`, `.skeleton`/`.spinner`/`.loading`, `.codeblock`, `.callout`, `.toast`, `.modal`. Use them before adding new styles. It is responsive down to phone width without horizontal scroll and honours `prefers-reduced-motion`.
- An agent's colour comes from its name (`hueOf` in `app.ts`, set as `--h`), picked from `NAME_HUES`, a palette clear of the ok/warn/bad/repair/accent hues; the landing diagram uses the same hues for agent-a/b/c. The live view's render functions stay as they are: a `MutationObserver` on `#pane-live` paints every `.agent` they add and makes log rows (and events that link to an entry) focusable buttons; Enter or Space selects them.
- Results of actions (created, invited, copied, landed) are toasts in `#toasts`, an `aria-live` region; a page's state (no access, a failed load) stays inline in its `.msg` line. Removing a member, leaving, withdrawing an invite and revoking a token ask first through `#confirm-dialog`.
- The Live tab's markup (`#pane-live` and its ids) is restyled from CSS only; other builds add panels inside it. A landed entry flashes once: `animationend` on `#log` takes it out of `state.live`.
- The skip link moves focus to `#content` in script: following `#content` would be read as a route.

## Rules
- It writes only through the API, as the signed-in user (repositories, members, tokens); the session cookie authenticates it, so no token sits in the page except a shared one pasted on a server without accounts.
- Message shapes come from `@pitstop/protocol` (type imports only).
- Deployed by CI like the server; never from a laptop.
- `npm run typecheck` covers it (the root script builds the protocol first).

## Not yet
- A worktree's name while it has no open intent: the heartbeat carries only `appliedLsn` and `intentId`, so naming it needs a field in `@pitstop/protocol` (both owners).
- An intent closed by a commit stays under Open intents until the page reloads: the server marks it committed (`Store.append`) but broadcasts `intent` only when one opens.
- A daemon that connects already at the head shows up only after its first heartbeat (after an apply, or the 30 s interval in `daemon/src/stream.ts`).
